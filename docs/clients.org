#+title: Clients

* Xray client

The Xray client is an optional local SOCKS5 and share-link client. Workstation
traffic normally uses sing-box. This client listens on =127.0.0.1:10800= and
prints VLESS share links when it is enabled. Set =xray_service_enabled= to
=false= to stop it without removing the package or rendered files.

The Xray client configuration is rendered to:

#+begin_src sh :results output silent
  $HOME/.config/xray/50-config.json
#+end_src

Validate it with:

#+begin_src sh :results output silent
  xray run -confdir=$HOME/.config/xray/ -dump
#+end_src

Logs are stored under =~/Library/Logs/xray/= on macOS. =xray_log_level=
defaults to =warning= and =xray_dns_log= defaults to =false=, so routine runs
do not record per-connection or DNS debug logs.

* sing-box

Workstation and OpenWrt use a configuration directory. The rendered profile is
=50-config.json=.

#+begin_src sh :results output silent
  sing-box check -C $HOME/.config/sing-box
  # OpenWrt:
  sing-box check -C /etc/sing-box
#+end_src

=sing_box_log_level= defaults to =info=. =debug= and =trace= are available for
short troubleshooting, but they are noisy on OpenWrt and iOS PacketTunnel.

The profile uses binary rule sets from
[[https://github.com/SagerNet/sing-geosite/tree/rule-set][SagerNet/sing-geosite/rule-set]].
When adding a route for one website, check the existing rule sets first and
prefer a suitable rule set over a one-off domain rule.

Non-OpenWrt profiles enable Tailscale SSH on the =ts-ep= endpoint. The tailnet
SSH ACL still decides who can connect and which local user the session uses.
The same endpoint accepts advertised routes, keeps LAN access when an exit node
is selected, and advertises itself as an exit node. On iOS App Store,
TestFlight, tvOS, and the macOS App Store build, sing-box ignores the SSH
server instead of failing the profile.

** OpenWrt peer relay

OpenWrt stays on sing-box 1.13 and renders one =ts-ep= endpoint. =ssh_server=
is a 1.14 field, so this endpoint does not set it, and it does not set
=advertise_exit_node=, =accept_routes=, or =exit_node_allow_lan_access=. It is
not an exit node. Routes for =100.64.0.0/10= and =ts.net= stay absent; the
relay listens on the host UDP port and does not depend on those routes.
The endpoint dials coordination itself, so route rules do not apply. On
OpenWrt its =detour= is =proxy-self=. A direct control connection stays open
without finishing login, while the working macOS client reaches the same
addresses through =proxy-self=.

=sing_box_tailscale_relay_server_port= defaults to =40000=. It is a role
default, so host or group vars can override it. =auth_key= still comes from
=sing_box_tailscale_auth_token=. The endpoint does not advertise a tag; assign
the tag in the Tailscale admin console. Do not change the auth key pass path.

The public relay address is not stored. =Network/Home/ASUS= subkey =ddns=,
overridable with =sing_box_asus_pass_path=, holds the DDNS hostname. Rendering
the OpenWrt profile resolves its A records with =community.dns= and writes
=relay_server_static_endpoints= as =ip:port=. Run the OpenWrt play again after
the public address changes. The field accepts an IP, not the hostname.

Tailnet policy must grant =tailscale.com/cap/relay= with =dst= set to the tag
assigned in the admin console. =src= is whichever nodes may use the relay. For
=tag:relay=:

#+begin_src json
{
  "grants": [
    {
      "src": ["autogroup:member"],
      "dst": ["tag:relay"],
      "app": {
        "tailscale.com/cap/relay": []
      }
    }
  ]
}
#+end_src

If the tag changes, point =dst= at that tag. This playbook does not edit the
tailnet policy.

Allow UDP =sing_box_tailscale_relay_server_port= on the OpenWrt firewall when
input is not already accepted. The OpenWrt role does not add or change that
firewall rule.

* Native service switches

Both switches default to =true=. Set one to the YAML boolean =false= to stop and
disable the installed service, skip install/config/export tasks, and retain the
package and files:

#+begin_src yaml
sing_box_service_enabled: false
xray_service_enabled: false
#+end_src

The switches support macOS, Linux, and OpenWrt. Restart handlers respect the
switch. The =service= tag is stop-only; to re-enable a service, restore =true=
and run the normal local workflow.

#+begin_src sh :results output silent
  make diff LIMIT=localhost TAGS=service \
    EXTRA="--inventory inventory.yml -e '{sing_box_service_enabled: false}'"
  make local TAGS=service \
    EXTRA="--inventory inventory.yml -e '{sing_box_service_enabled: false}'"
#+end_src

Although =xray_group= includes the VPS and localhost, it currently supplies
Xray variables only. The main playbook does not include =xray_client= for the
VPS.

* macOS gateway

The optional =gateway= tag enables IPv4 forwarding for same-LAN clients using
the workstation TUN. Reserve the Mac LAN address in the main router, configure
one test client to use it as gateway, use a public IPv4 DNS address, and disable
IPv6 on the test client.

This does not configure PF/NAT, DHCP, or an IPv6 gateway. The Mac must remain
awake and logged in. If sing-box stops, traffic may fall back to the main router.

#+begin_src sh :results output silent
  make diff LIMIT=localhost TAGS=gateway
  make local TAGS=gateway EXTRA="-K"
#+end_src

To disable forwarding immediately:

#+begin_src sh :results output silent
  sudo sysctl -w net.inet.ip.forwarding=0 net.inet.ip.redirect=1
#+end_src

* Routing notes

The =proxy-iv-remote= VMess/WebSocket/TLS outbound reads credentials and
connection settings from =Work/IV/Proxy= via =invalley_pass_path=. Every
profile, IV or not, routes =invalley.co= through this outbound before Tailscale
and general direct-routing rules. TUN routes stay at the platform defaults.
Portable Windows and iCloud profiles omit local site-specific outbounds.

* iCloud profile

#+begin_src sh :results output silent
  make local TAGS=icloud
#+end_src

The profile is exported to the sing-box iCloud container at
=iCloud Drive/sing-box/sing-box.json=. The iCloud profile omits host-local logs,
the loopback API/dashboard, and site-local outbounds.

* Windows profile

#+begin_src sh :results output silent
  make local TAGS=windows
#+end_src

The profile is exported to
=~/.config/sing-box/windows/sing-box.json=. Copy it to Windows. TUN requires
an elevated process and the =wintun= DLL supplied by the sing-box package.

#+begin_example
sing-box.exe run -c sing-box.json --directory %LOCALAPPDATA%\sing-box
#+end_example

The Windows profile keeps the loopback API/dashboard, Tailscale, and the remote
Invalley outbound, but omits host-local logs and site-local outbounds.
