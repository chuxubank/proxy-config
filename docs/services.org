#+title: Services and VPS Placement

* Placement model

Each VPS declares one complete =proxy_services= list in
=host_vars/<hostname>.yml=. Removing a service disables its container on the next
normal deployment. An empty list disables the managed Compose project.

The current inventory has one VPS, =bwg-cn2-gia=. Its complete list is maintained
in =host_vars/bwg-cn2-gia.yml=. Only the proxy path is selected in inventory;
monitoring, RSS, and asspp services are configured as disabled. This table describes
the desired state; apply the deployment to update the running VPS.

* Current service table

| Service | Purpose | Runtime dependencies | Current VPS |
|---+---+---+---|
| =caddy= | HTTPS/TLS entrypoint, reverse proxy, static files, and metrics | — | =bwg-cn2-gia= |
| =xray= | Xray proxy server | =caddy= | =bwg-cn2-gia= |
| =warp= | WARP SOCKS5 outbound | — | =bwg-cn2-gia= |
| =prometheus= | Metrics collection and time-series storage | — | Disabled |
| =grafana= | Monitoring dashboards | — | Disabled |
| =freshrss= | RSS reader | — | Disabled |
| =rsshub= | RSS content aggregation | =redis=, =browserless= | Disabled |
| =redis= | RSSHub cache | — | Disabled |
| =browserless= | Headless Chrome used by RSSHub | — | Disabled |
| =asspp= | assppweb application | — | Disabled |

The proxy services are selected for =bwg-cn2-gia=. The other Compose services
remain defined in the native files but are not selected. Docker-internal service
names and Caddy routes are local to the Compose project.

Service definitions, environment variables, and secret paths are retained.
To re-enable a service, add it and its dependencies back to the host's
=proxy_services= list and deploy that host.

* Service configuration

#+begin_src yaml
# host_vars/bwg-cn2-gia.yml
proxy_services:
  - caddy
  - xray
  - warp
#+end_src

Compose files remain native. Every service has a matching Compose profile, and
Compose validates the dependency graph before containers are stopped. The old
=proxy_profile=, allowlist, and denylist variables are no longer used.

Caddy routes are rendered only for selected local services. If =warp= is omitted,
Xray's clean-IP routes use =direct= instead of a WARP outbound.

* Applying changes

A normal deployment pulls selected images, then runs =down/up=. This removes
containers for disabled services and reloads bind-mounted configuration even
after a failed previous attempt. There is brief whole-project downtime. Named
volumes and bind-mounted application data are retained.

#+begin_src sh :results output silent
  make diff LIMIT=bwg-cn2-gia
  make server LIMIT=bwg-cn2-gia
#+end_src

=make pull= only pulls selected images and never stops or starts containers. Run
a normal deployment first after changing =proxy_services= so that the Compose
files and environment are synchronized.

* Adding or moving a VPS

1. Add the host to =vps_group= in =inventory.yml=.
2. Add its connection and secret-path variables.
3. Add =host_vars/<hostname>.yml= with a complete =proxy_services= list.
4. Run =make diff LIMIT=<hostname>=.
5. Deploy the new host and explicitly migrate any application data.

Changing a service list is not a data migration. DNS, published ports, remote
reverse-proxy targets, and persistent data must be handled separately.
